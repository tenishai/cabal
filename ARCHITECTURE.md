# cabal — repo card

WHAT: the platform's orchestrator ("Cabal Core"): a self-hosted FastAPI daemon that is the IdP (RS256 JWT mint/verify, JWKS), the A2A dispatch broker between agents, the bulletin board of registered agents, and the encrypted credential store, plus the LLM personas (architect, archivist, librarian, mason, wright) that run inside it.
STATE: main, v0.5.0 (pyproject; distribution `tenish-cabal`, import name `cabal`; `cabal.__version__` reads that package's metadata), classifier Pre-Alpha, MIT. Recent work (git log): the A2A v1.0 interface at /agents/{name}/a2a, one shared dispatch-auth policy, detached dispatch, exact-match secrets lookups, operator-only handler flags; 0.3.1 added `cabal.bootstrap_code`, 0.3.2 the `colleague_invite` remedy on a missing-pair refusal, and 0.4.0 the archivist hardening (supersede on publish, quoted FTS5 tokens, typed handler fields, one-transaction publishes, `cbl archivist purge`), `cbl guide`, and the exact litellm pin. 0.5.0rc1 adds running tasks and a drain (issue 405), scheduled tasks and the 705 waiting outcome (issue 406), and archivist origin, access labels, lineage and erasure (issue 410). 0.5.0 adds, since rc1: the review engine, watch loop and merge gate (`cbl review`, issue 399), dispatch to a group (`[groups]`, issue 423) and an answer path for any task in `input-required` (issue 145), fan-out token budgets and the token meter (issue 394), `GET /auth/revocations`, the LiteLLM Proxy image pinned by digest, and the MIT licence.
STACK: Python ≥3.12 (CI 3.12/3.13). FastAPI + uvicorn, SQLAlchemy async + aiosqlite (SQLite only), Alembic (revisions under src/cabal/migrations/versions, shipped as package data), pydantic-settings, Typer, cryptography (Fernet), joserfc (JWT/JWS; declared directly), httpx, structlog, litellm (hard dep, lazily imported; pinned ==1.104.2 after the 1.107.0 supply-chain compromise, Dependabot ignores it, a bump is a reviewed line). Extras: `mcp` (`tenish-liminal` ≥0.4), `memory` (`tenish-techne` ≥0.18.2), `full`, `tui` (textual), `dev`. Install: `pip install -e ".[dev]"`; siblings as editable checkouts `-e ../techne -e ../liminal` (git pins in requirements-sources.txt). Dockerfile CMD = `cbl daemon up --host 0.0.0.0 --port 7400 --config /app/identity.toml`; docker-compose*.yml, k8s/ manifests, Makefile (dev compose stack, `make bootstrap`).

GOTCHAS:
- cabal is the orchestrator/IdP/broker, NOT the MCP gateway (that is liminal) and NOT the memory store (that is techne). core/ speaks A2A; handlers/ speak liminal MCP. Dispatch logic in a handler is the wrong layer.
- Dispatch-token policy lives once in routes/_dispatch_auth.py; the REST, legacy JSON-RPC and v1.0 doors only translate refusals, and the TUI's in-process client keeps an operator-only variant (dispatch-auth.md). Change policy there, not in a door.
- Master key: `CABAL_MASTER_KEY` encrypts signing keys AND secrets. A changed key fails startup with a specific message; recovery is `cbl reset-auth`, never guessing keys.
- role="primus" personas register as `<name>-primus` (e.g. mason-primus).
- `make test-unit` and `make test-integration` run the same `pytest -q` (AGENTS.md).
- `identity.toml` is gitignored; edit `identity.toml.example`. `[limenal]` (old spelling) is otherwise ignored. It logs `identity.unknown_section` at config load; then, because `[liminal].url` stays unset, each MCP-enabled persona logs `personas.mcp_skipped` at startup (a warning that also fires when the signing key or HTTP client is missing, and records which one).
- There is no secrets-backend plugin discovery (nothing reads an entry-point group `cabal.secrets_backends`; cabal#235); a new backend means editing app.py.
- AgentCards are signed but never verified on dispatch (router docstring, #226).
- STATUS.md is a June 2026 historical record; docs/proposals/ are design notes, several stale.
