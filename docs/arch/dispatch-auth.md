# dispatch-auth — JWT realms, scopes, and the re-mint doors

WHAT / SEAM: every credential is an RS256 JWT minted by `jwt.mint` (core/auth/jwt.py; iss "cabal-core", claims `cabal_persona`, `cabal_scope`, `cabal_tool_extras`; default TTL 5 min) and checked by `jwt.verify` (alg pinned RS256) against the JWKS served at `/.well-known/jwks.json`. Revocation: `revocations.refusal(...)` by subject+iat, checked at every door.
TOKEN KINDS (who mints → aud / scope):
- operator: POST /auth/bootstrap with the one-shot startup code → sub `operator:<operator_id>`, aud "cabal-core", scope [operator], `[cabal] operator_token_ttl_seconds` (default 1h) (`routes/auth.py` `bootstrap`). POST /auth/renew swaps a still-valid, unrevoked operator token for a fresh one with the same subject (`renew`); `cbl` renews a saved one with under 10 min left (`cli/client.py` `TokenStore.load`) (#395).
- persona bootstrap: same route, persona code → aud=<persona>, scope [dispatch].
- colleague: minted OUTSIDE cabal by the room (kobo), sub `agent:<name>`, aud "cabal-core", scope [colleague]. Grants GET /directory, dispatch re-mint, and POST /auth/liminal-token (15-min aud=gateway token).
- service: POST /admin/token/mint-service (operator only; ≤365 days; refuses operator scope and an `operator:` sub, #403), e.g. scope secrets-fetch for liminal.
- per-target dispatch: re-minted by the doors below, aud=<target> (or the federated peer's `federation_audience`), scope ["dispatch"].
- persona→liminal: minted per call in persona_factory.py (aud `[liminal] jwt_aud`), see liminal-boundary.md.
OPS / FLOW: caller token → door `_resolve_dispatch_token` (a thin wrapper) → `_dispatch_auth.dispatch_token`: verify + revocation, resolve the target's audience (`dispatch_audience`), token already aimed at it? forward as-is : require operator|colleague scope and a non-empty `sub` → (non-operator) `dispatch_pairs.is_allowed(caller=sub, target)` → re-mint per-target token → `DispatchRouter.dispatch` verifies it again (dispatch-router.md). Every `DispatchRefusal` is recorded once in `dispatch_token` (cabal#315): a `dispatch.refused` warning naming caller, target, kind, reason and `check` (token, revoked, audience, scope, sub, pair, signing_key), with caller, target and reason capped at 128 chars, never the token; plus a `dispatch_refused` events row only when the caller's token verified, so an unauthenticated request never writes to the database.
INVARIANTS:
- ONE POLICY, MANY DOORS. The re-mint policy lives once in `routes/_dispatch_auth.dispatch_token` (cabal#234, #285); the REST door (routes/tasks.py `_resolve_dispatch_token`, POST /a2a/tasks), the legacy JSON-RPC door (routes/a2a_jsonrpc.py `_resolve_dispatch_token`, POST /agents/{name}) and the A2A v1.0 door (routes/a2a_v1.py) only translate a `DispatchRefusal` into their own wire form. Change policy there, never in a door: the old per-door copies drifted, and a pairs check once missing from one was a full bypass. The TUI's in-process client (tui/client/inprocess.py `InProcessBrokerClient`) keeps its own operator-only re-mint but takes the audience from `dispatch_audience`.
- Wire forms differ on purpose: REST answers 401/403/500 with `{"detail": message}`; legacy JSON-RPC maps a pairs refusal to FORBIDDEN, other refusals to UNAUTHORIZED (`legacy_forbidden`), server faults to INTERNAL. A refusal with a `remedy` code (only the pairs check today: `colleague_invite`, cabal#329) carries it next to the message: a top-level `remedy` beside `detail` on REST and v1.0 (`DispatchRefusal.body_fields`), and the error's `data` on legacy JSON-RPC, both `message/send` and the `/stream` door's SSE error event. `detail` stays a string, because daedalus 0.5.0's `_refusal_detail` (tools/colleagues.py) passes the body's `detail` through `str()` into the text the model sees. A `federated` target's token gets aud=`federation_audience` at every door; a federated row with none is a 500/INTERNAL.
- A token with no `sub` is refused (401), not re-minted as "operator" (cabal#184).
- The `cabal_` metadata prefix is cabal's on an inbound task (cabal#401): every door (REST /a2a/tasks, JSON-RPC message/send and message/stream, v1 SendMessage) passes caller metadata through `core/a2a/inbound.inbound_metadata`, which drops every `cabal_*` key except `cabal_delegation_depth` and `cabal_trace_id` (CALLER_DECLARED). So a caller can't set its own token budget, place its task under another in the AbortGraph, or skip SESSION_START. A new door must call it too.
- Re-mint hard-codes scope=["dispatch"]; the caller's operator scope does not survive into the router (open, cabal#164). A router-level guard cannot ask "is this the operator?".
- dispatch_pairs: EMPTY TABLE = OPEN (D-018). Room syncs the whole set atomically with PUT /admin/dispatch-pairs (operator), which logs the stored count, as a `dispatch_pairs.replaced_empty` warning when it is zero (cabal#315). Operators skip the check. WHY: deploy-safe; cabal stores policy, kobo decides it. GET /directory applies the same pairs to a colleague via `dispatch_pairs.allowed_targets` (None = empty table = everyone), so it lists only targets re-mint would allow; operators see the full roster (cabal#321).
- 401 = no/bad signature, expired, revoked; 403 = valid token, wrong audience or scope (D-017), uniformly across guards. Admin guards all go through `admin._require_scope`; /auth/liminal-token still inlines its own gate (noted in its docstring as a follow-up).
- Revocation is subject-wide (`iat < not_before`, core/auth/revocations.py), held in process memory and written through to a table. WHY it matters: correct only for ONE uvicorn worker; adding workers means moving the lookup to the table. aud=gateway tokens are verified by liminal and live out their 15 min after a revoke.
- Colleague tokens must 403 on every /admin route (routes/directory.py docstring; tests/test_colleague_scope.py).
- `jwt.AGENT_SUB_PREFIX` ("agent:") is the sub shape of colleague and outside-agent tokens; the delegation-edge guardrail keys on it (`caller_edges`, cabal#189).
CONSUMERS: cli/client.py (cbl), tui/client, liminal (verifies cabal JWTs via JWKS), kobo (mints colleague tokens, syncs pairs).
